# AGENTS.md

## Project overview

**Invita** is a digital wedding invitation platform with two audiences:

1. **Product landing page** (`/`) — sells the service to engaged couples in Spanish. Marketing copy, zero technical jargon.
2. **Admin panel** (`/admin`) — private tool used only by the business owner to manage client invitations, RSVPs, and leads.
3. **Public invitations** (`/[slug]`) — the actual wedding invitation page delivered to each couple's guests, rendered from data stored per invitation.

Current business model: manual/service-based. The owner loads each client's data herself through the admin panel — there is no self-service client editor yet. Do not build a self-service flow unless explicitly asked.

## Tech stack

- Next.js (App Router) + TypeScript
- Tailwind CSS
- Framer Motion (animations, used on the landing and public invitations — not required in the admin)
- TanStack Query + Axios (client-side data fetching for the admin)
- Zod (all form and API input validation)
- Postgres via Supabase (database + auth + storage)
- Vercel (hosting)

Do not introduce a different state management library, CSS framework, or backend runtime without asking — these choices are deliberate and already validated against the owner's existing skill set.

## Commands

```
pnpm run dev       # start local dev server
pnpm run build     # production build
pnpm run lint      # lint
pnpm run typecheck # next typegen && tsc --noEmit
```

All four scripts exist in `package.json`. Next.js 16 removed `next lint`, so `lint` runs `eslint` directly, and `typecheck` runs `next typegen` before `tsc` because route types (`LayoutProps`, `PageProps`) are generated by Next — that is expected, not a mistake.

## Design system

Use these tokens **only** on the product landing page and public invitation pages. The admin panel should stay visually neutral (e.g. shadcn/ui defaults) — it's a tool for the owner, not a branded surface.

- Colors: forest green `#1F3A2E` (primary), ivory `#FBF8F2` (background), aged gold `#B08D57` (accent), ink `#1A1A17` (text), sage green `#8FA396` (secondary text on dark backgrounds)
- Typography: Fraunces for display/headers, a calligraphic script (e.g. Mrs Saint Delafield or italic Cormorant Garamond) reserved for couple names only, Inter for body/UI text
- Motion principle: one deliberate "hero" animation moment (e.g. the envelope-opening gate) may pulse or animate without user input; everything else should be triggered by scroll or explicit user action — avoid generic fade-in-on-every-section patterns
- Explicitly avoid: cream+terracotta gradient backgrounds, rounded cards with identical generic gray drop shadows, uppercase eyebrow labels stacked above every single heading

## Data model

Postgres schema — treat as the source of truth. Don't rename fields or restructure tables without confirming first.

```sql
invitations (id, slug, template_id, status, couple_a, couple_b,
  wedding_date, intro_text, hero_photo_url, quote, dress_code_label,
  dress_code_note, gift_note, gift_bank_titular, gift_bank_banco,
  gift_bank_cuenta, allow_kids, rsvp_deadline, created_at)

invitation_photos (id, invitation_id, url, order)
schedule_items (id, invitation_id, time, label, icon, order)
locations (id, invitation_id, type, name, address, maps_url)
rsvps (id, invitation_id, guest_name, attending, guests_count, message, created_at)
leads (id, name, wedding_date, contact, message, status, created_at)
```

`status` is always `'draft' | 'published'`. `locations.type` is always `'ceremony' | 'reception'`.

## Route structure

```
app/page.tsx                          product landing page
app/[slug]/page.tsx                   public invitation (renders WeddingInvitation component)
app/admin/page.tsx                    admin dashboard
app/admin/invitations/new             create invitation
app/admin/invitations/[id]/edit       edit invitation
app/admin/invitations/[id]/rsvps      view RSVPs for one invitation
app/admin/leads                       leads captured from the landing page
app/api/rsvp/route.ts                 POST — guest submits RSVP
app/api/leads/route.ts                POST — landing page "get a quote" form
app/api/invitations/[slug]/route.ts   GET — public invitation data by slug
```

`/admin/**` must be auth-protected. Never expose admin routes or link to them from public-facing pages.

## Key components

- `WeddingInvitation.tsx` — the reusable public invitation template. Takes a single `data` prop shaped like the tables above joined into one object. New visual themes must accept the same `data` shape so they stay interchangeable. Do not hardcode couple-specific content inside this component — it always comes from props.

## Conventions

- All user-facing copy on the landing page and public invitations is in **Spanish**. Code, comments, and this file are in English.
- Slugs are auto-generated from `couple_a` + `couple_b` (e.g. "camila-y-sebastian"), kebab-case, with a manual override field in the admin form in case of collisions.
- Mobile-first: most guests open invitations from a WhatsApp link on a phone. Test every public-facing page at a 375px viewport before anything wider.
- Respect `prefers-reduced-motion` in all Framer Motion usage.
- Photo uploads go to Supabase Storage, not committed to the repo and not stored as base64 in the database.

## Working style

Build feature by feature, following whatever roadmap or phase the owner specifies in the conversation — don't jump ahead to later phases (e.g. self-service client editor, payments, multi-theme system) unless asked. Don't silently change the stack, data model, or design tokens above; if one seems wrong for a specific task, flag it and ask before deviating.
